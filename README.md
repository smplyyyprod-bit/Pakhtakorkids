# Система учёта работы тренеров

Telegram-бот для ежедневного учёта посещаемости, рабочих часов, дисциплины и
месячной статистики спортивных тренеров.

---

## Что проверено, а что нет

Честный статус на момент последнего коммита.

**Проверено запуском** (`scripts/verify.py`, `scripts/verify_handlers.py` —
71 проверка, все проходят):

- миграция Alembic применяется на чистой PostgreSQL 16;
- 51 тренер, 3 отделения, 1020 ежедневных записей за 20 дней;
- автосоздание записей идемпотентно (повторный запуск создаёт 0 дублей);
- расчёт часов, включая ночную смену через полночь;
- месячная агрегация, рейтинги, сравнение, динамика явки;
- экспорт `.xlsx` и `.pdf`, в PDF встраивается кириллический шрифт;
- журнал аудита пишется при каждом изменении;
- все 12 команд, разграничение ролей, полный цикл заполнения отчёта
  через реальные Telegram-апдейты (транспорт замокан).

**Не проверено:**

- живое соединение с `api.telegram.org` — окружение разработки блокирует этот
  хост, поэтому реальный обмен с Telegram не выполнялся. Всё до сетевого
  вызова работает; сам вызов нужно проверить при первом запуске на сервере;
- работа под нагрузкой и на длительном отрезке времени;
- Redis как хранилище FSM (код есть, но прогонялся только in-memory).

## Возможности

**Администратор** — заполняет ежедневные отчёты.
Выбирает отделение, бот сразу открывает первого незаполненного тренера,
после сохранения автоматически переходит к следующему. Аналитика компании
недоступна — это ограничение на уровне роутера, а не проверка внутри обработчика.

**Руководитель** — статистика, рейтинги, выгрузки, администрирование.

**Ежедневная форма:** присутствие, верхняя и нижняя форма, время начала и
окончания (часы считаются автоматически), опоздание, ранний уход, примечания.
Почти всё — кнопками.

**Гарантия отсутствия пропусков.** На каждого активного тренера каждый день
создаётся запись. Незаполненная запись существует со значениями по умолчанию
(0 часов, «не заполнено») и попадает в месячную статистику. Гарантию держит
уникальный индекс `(coach_id, report_date)` в базе, а не логика приложения,
поэтому повторный или параллельный запуск планировщика безопасен.

**Автоматические расчёты:** отработанные часы и дни, опоздания и суммарные
минуты, ранние уходы, дни без формы, больничные, отпуска, прогулы.

**Выгрузки:** Excel и PDF с помесячной таблицей, итогами и подсветкой
незаполненных дней.

**Уведомления:** вечернее напоминание о незаполненных отчётах и месячная сводка.

## Архитектура

```
app/
├── core/                    конфигурация, логирование
├── domain/models/           сущности (SQLAlchemy ORM)
├── infrastructure/
│   ├── database/            движок, сессии, сидинг
│   ├── repositories/        доступ к данным, SQL-агрегация
│   ├── services/            бизнес-логика
│   └── scheduler/           периодические задачи
└── presentation/telegram/
    ├── handlers/            обработчики команд и кнопок
    ├── keyboards/           инлайн-клавиатуры
    ├── middlewares/         сессия БД, аутентификация, ошибки
    ├── filters/             проверка ролей
    ├── callbacks/           типизированные callback data
    └── utils/               FSM-состояния, форматирование
```

Слои разделены: обработчики не знают про SQL, репозитории не знают про Telegram.
Сессия БД и текущий пользователь приходят через middleware.

### Две детали, которые стоит знать при доработке

**Middleware зарегистрированы как `outer_middleware`.** aiogram вычисляет
фильтры обработчика до внутренних middleware. Если зарегистрировать
аутентификацию как `middleware`, фильтр роли не увидит пользователя и
весь раздел руководителя молча перестанет отвечать.

**В FSM-состоянии хранятся только примитивы.** ORM-объект, положенный в
состояние, отвязывается от сессии, и первое же обращение к его связи падает.

## Установка

### Docker (рекомендуется)

```bash
git clone -b claude/telegram-bots-capability-i86t61 \
  git@github.com:smplyyyprod-bit/Pakhtakorkids.git
cd Pakhtakorkids

cp .env.example .env
nano .env        # TELEGRAM_BOT_TOKEN, TELEGRAM_ADMIN_IDS, DB_PASSWORD

docker compose up -d
docker compose logs -f bot
```

Миграции применяются автоматически при старте контейнера.

### Локально

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env && nano .env
alembic upgrade head
python main.py
```

Для PDF нужен шрифт с кириллицей:
`sudo apt install fonts-dejavu-core` (в образ уже включён).

## Доступ

Доступ выдаётся только явно. Неизвестный Telegram ID получает отказ — бот не
повышает права сам по себе.

```env
TELEGRAM_ADMIN_IDS=123456789,987654321
TELEGRAM_MANAGER_IDS=555555555
```

Список читается при каждом старте: добавили ID, перезапустили — доступ есть.
Свой ID можно узнать у `@userinfobot`.

## Команды

Меню команд публикуется из кода (`setMyCommands` со скоупами), поэтому
администратор и руководитель видят разные списки. Настраивать список в
BotFather не нужно — код его перезапишет.

| Администратор | |
|---|---|
| `/start` | главное меню |
| `/branches` | выбрать отделение и заполнять отчёты |
| `/today` | статус за сегодня |
| `/edit` | изменить отчёт |
| `/cancel` | прервать заполнение |
| `/help` | справка |

| Руководитель | |
|---|---|
| `/start` | главное меню |
| `/coaches` | список тренеров |
| `/monthly` | месячная статистика |
| `/dashboard` | сводка по компании |
| `/analytics` | рейтинги |
| `/export` | выгрузка Excel / PDF |
| `/admin` | администрирование |
| `/cancel` | сбросить действие |
| `/help` | справка |

```bash
python -m scripts.verify           # данные, расчёты, агрегация, выгрузки
python -m scripts.verify_handlers  # команды, роли, полный цикл формы
```

## Расширение

Критерии оценки хранятся в таблицах `evaluation_criteria` и
`criterion_values`, поэтому новый критерий — это INSERT, а не правка кода.

Слоистая структура оставляет место для зарплат, расписаний, заявок на отпуск,
REST API и веб-панели: добавляется репозиторий, сервис и точка входа,
доменные модели и существующие обработчики не трогаются.
